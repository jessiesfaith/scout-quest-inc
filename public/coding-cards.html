The honest read

✔ Pros

  • Elite context engineering. Your agent-state memory + handoffs mean sessions compound instead of starting cold — rare and valuable.
  • Real verification discipline. Browser preview-eval + adversarial multi-agent review actually caught real bugs (the idle-monitor heartbeat bug). Not vibe-shipped.
  • High-leverage orchestration. 36 workflows and 788 subagents mean you scale yourself, not just your prompts.
  • Decisive operating loop. Terse “approved / go / push” + continuous deploy = a genuinely tight ship. 456 commits into a live product.
  • Security baked in early. RLS, audit logging, retention, anti-exfiltration — rare for a solo build, essential for K-12.

△ Watch-outs

  • No automated safety net. No test suite, lint, or CI — regressions rely on you remembering to review. Gets riskier as the surface grows.
  • Giant single-file pages. student.html alone has 162 revisions; 100k-line files are hard to diff and hard for agents to edit safely.
  • Bus factor of one. 455 of 456 commits are yours. The durable docs help, but the knowledge is concentrated.
  • Intense, late cadence. Midnight peaks and 56-commit days are great for a sprint, a burnout risk over months.
  • Terse prompts can under-specify. Nearly half are under 10 words; “go / do all” occasionally leaves the agent guessing.

→ Going forward

  • Add a thin test net. A handful of Playwright smoke tests + a deploy-time CI check, so agent reviews spend their effort on logic, not regressions.
  • Codify the adversarial review as a reusable skill/command so every feature gets the same rigor automatically.
  • Finish the Next.js move (this repo!) to retire the giant HTML files — components make diffs and multi-agent edits far cleaner.
  • Track agent cost per feature so the fleet stays economical as you scale the workflows.
  • One-line acceptance criteria. Append “…and it must still pass X” to the terse prompts to cut re-work without slowing you down.
